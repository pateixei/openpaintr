# OpenPaintR Project Rules

- Rasterize lines, curves, strokes, fills, and selections with **4×4 SSAA** enabled at all times, both in previews and in pixels committed to a layer.
- Every tool that selects, fills, or replaces pixels based on color similarity must offer **Color Tolerance (0–100%)** in its contextual toolbar. Reuse the reference-color comparison and handle alpha consistently across tools. At 0%, require an exact match under the selected alpha mode. Keep tolerance independent of contiguous or global scope, the sampling source, and SSAA coverage.
- Every tool that creates a selection must offer **Feather (0–100%)** in its contextual toolbar. At 0%, preserve the original selection's SSAA coverage. At 100%, the linear outward transition has a radius equal to half the shorter side of the selection's bounding box. Clip the mask to the canvas and use its partial coverage in previews and editing operations.
- When implementing a tool, register its action in the central shortcut system with a stable identifier and a configurable binding. Update the [`atalhos.json` schema](docs/atalhos.schema.json) and the applicable Paint.NET and Adobe profile mappings. Preserve existing customizations as the schema evolves.
- For each tool, panel, or action, implement equivalent mouse shortcuts documented for Paint.NET or Adobe Photoshop. Register gestures in the configurable shortcut system, the JSON schema, and the relevant profiles. Record gestures that depend on pending features in the roadmap.
- Implement every effect in the **Effects** menu exclusively as a portable, cross-platform OpenPaintR plugin. A `.rpdn-plugin` package contains **WebAssembly, optional `WGSL` shaders, and a declarative UI**. Use only the public API available to third-party extensions. Keep the minimal SDK (`rustpdn-plugin-sdk`), [plugin architecture](docs/arquitetura-plugins.md), and [extensibility guide](docs/extensibilidade.md) in sync.
- Follow the [roadmap](docs/roadmap.md) for acceptance criteria and delivery order.
- When a roadmap item meets its acceptance criteria, summarize the result and verification evidence and request the project owner's explicit sign-off. Keep the item open in the roadmap and hold its GitHub update until sign-off arrives. After approval, mark the item complete in the roadmap and push the approved changes to GitHub.
- Keep repository documentation and GitHub project descriptions in English.
